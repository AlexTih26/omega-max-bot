# Этапы 3–5 новой Таксимо: рейс, ТТН, ЭР (коммит f679709)

Ветка `kodik/new-taksimo-integration`. Миграция `012` **применена** 12.10.2026.
Рабочая база: 13 миграций, 40 таблиц.

## Цепочка документов

диспетчер создаёт рейс → выдаёт номер ТТН → печатает 4 экземпляра →
бухгалтер готовит ЭР → отмечает «отправлено» → «вернулось» → оператор
принимает машину на площадке (приёмка была уже с Этапа 1).

## Таблицы (миграция 012)

- `tn_trips` — рейс; статусы `draft → ttn_issued → printed → er_sent →
  er_returned / cancelled`. Хранит **снимок** водителя, перевозчика,
  машины: правка справочника не переписывает прошлое.
- `tn_trip_blocks` — блоки рейса со снимком веса и стоимости.
- `tn_ttn_numbers` — номер `ТТН №РМ-ГГГГ-ЧЧЧЧЧЧ`, UNIQUE по trip_id.
- `tn_ttn_copies` — 4 экземпляра xlsx с sha256 и size_bytes.
- `tn_expedition_receipts` — ЭР, статусы `draft/sent/returned/cancelled`.
- `tn_intakes.trip_id` — связь приёмки с рейсом.

## Правила, которые нельзя нарушать

- **ТТН печатается только с полными данными.** Без ФИО водителя, прав и
  модели машины построение отклоняется: пустой бланк выдавать нельзя.
- **3–6 блоков на рейс** — ограничение утверждённого бланка.
- **Права ролей:** рейс создаёт только диспетчер (админ тоже), ЭР — только
  бухгалтер. Оператор получает 403.
- Номер ТТН неизменяем; повторный вызов возвращает тот же номер.

## Найденные и исправленные баги

- `_row_datetime` не преобразовывал `Decimal` → JSON падал с 500 на
  `/admin/catalogs`, как только в справочнике появлялась цена плиты.
  Исправлено, добавлен `from decimal import Decimal`.
- API передавал `remote_address` в функции, которые его не принимают.
- `_secret()` не подгружал закрытый конфиг → `/auth/check` отдавал
  `configured: false` (исправлено ранее).

## Открытый риск: нумерация ТТН

Новая Таксимо ведёт **свою** последовательность номеров, РУМЕКС — свою
(`test_ttn_number_sequences`). Пока контуры работают параллельно, номера
**пересекаются**: у рейса новой Таксимо и у РУМЕКС может быть один и тот
же «ТТН №РМ-2026-000001».

Решение отложено: читать последовательность РУМЕКС означает писать в его
SQLite, что нарушает границу контуров до переключения. **Перед датой X
последовательности нужно выровнять**, иначе в бухгалтерии будут дубли
номеров. Это же касается блока «блоки заводятся вручную» — при переносе
состояния возможны расхождения.

## Проверено

Сквозной сценарий через HTTPS на живой базе: рейс с водителем и
перевозчиком → `ТТН №РМ-2026-000003` → 4 экземпляра (43 708–43 710 байт) →
скачивание → содержимое бланка верное (водитель с инициалами, права,
машина, вес 23 760 кг, три блока) → ЭР создана, отправлена, вернулась.

Дата в ТТН печатается в рабочем поясе площадки (`Asia/Irkutsk`): рейс
создан 12.10 17:07 UTC → в бланке 13.10. Это правильно, не баг.

64 теста новой Таксимо зелёные. Тестовые данные удалены, учётки вернулись
в исходное состояние (активны три оператора, остальные отключены).
