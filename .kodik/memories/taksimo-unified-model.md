# Согласованная целевая модель (Этап 0, 12.10.2026)

Это **решение владельца продукта**, а не описание текущего кода. Текущий код
описан в `README.md` (до переписывания) и в памяти
`taksimo-new-legacy-integration.md`. Новая модель **отменяет** изоляцию
контуров РУМЕКС ↔ новая Таксимо.

## Суть

Одна программа на **MySQL**, документы и физика в **одной БД**. Мост
`rumex_taksimo_bridge.py` и изоляция контуров больше не нужны. Старая Таксимо
(`data/taksimo.db`) **не трогается**, остаётся источником правил, сетки, тупиков
и опыта, пока новая её не заменит. Новая Таксимо = старая по духу, на MySQL,
с ролями и документами.

## Роли и учётки (8)

- `админ` — справочники и «решалa»: машины, вагоны (~60), блоки, правила;
- `диспетчер` — Северомуйск: приёмка блоков, рождение блока, ТТН;
- `бухгалтер 1`, `бухгалтер 2`, `бухгалтер 3` — Москва (ООО Омега-М);
- `оператор 1`, `оператор 2`, `оператор 3` — станция Таксимо.

Операторы — логин по фамилии или e-mail. В истории фиксируется **кто именно**
(«оператор 2, Иванов»), это часть прослеживаемости.
Авторизация одна, **входы по ролям**, плюс **детальный журнал действий**
(кто что сделал/сохранил).

## Учётные единицы

- **Блок** — самая мелкая единица. `буква + номер + вес + стоимость`,
  **id с рождения**. Рождается **у диспетчера при приёмке**: вносит букву,
  номер, хвост машины. Вся история рейсов/машин/вагонов = история
  **перемещений блоков**.
- **Машина** — справочник, гос.номер = идентификатор. История = список рейсов;
  «сколько раз сходила» = фильтр по журналу. Ходят одни и те же машины.
- **Рейс** — 7 блоков, хранит **снимок** водителя и перевозчика на момент рейса.
- **Перевозчик** — справочник (ООО или ИП, + ИНН), добавляется один раз.
  **Водитель** — справочник, может меняться между рейсами.
- **Вагон** — парк ~60, добавляет админ. **Схема вагона — сущность**:
  присваивается **перед постановкой порожнего вагона в тупик** (как в старой).
  От схемы зависит максимум плит: 9 / 8 / 16.
- **Фото** — кнопка есть, за ней заглушка. S3 (Яндекс или Сбер) — позже,
  отдельным контуром, по цене.

## Вес и стоимость

Справочник **по буквам**, общий: `A=7780  B=7900  C=8080  D=8080  E=7900
F=7780  K=3850` кг. **Подтверждены владельцем 12.10.2026** — пометка
«предварительные» устарела. В истории рейса/документа сохраняется **снимок**
веса и стоимости: изменение справочника не меняет прошлое.

## Доменные правила (наследуются от старой Таксимо)

- буквы: `A–F`, `K`; суффиксы: `""`, `к`, `а`, `тк`, `скол`;
- рабочие зоны: `ХРАНЕНИЯ`, `ГРУЗОВОЙ`, `ТУРАН`, третий тупик;
- системные зоны: `В КОДАР`, `БТС ВОСТОК`;
- сетка склада `13 × 25`, макс. 4 плиты в ячейке;
- макс. плит в вагоне 9 / 8 / 16 — **по схеме вагона**;
- **три** тупика по 10 мест: `ГРУЗОВОЙ`, `ТУРАН`, третий.

## События вагона

Приезд, отправка в Кодар, выгрузка у БТС Восток, возврат в Таксимо,
**перестановки между тупиками** (Грузовой ↔ Туран ↔ третий). Схема
присваивается перед постановкой в тупик.

## ЭР (экспедиторская расписка)

Ручной документ бухгалтера. Бухгалтер сам переносит данные в Диадок/Контур и
жмёт в нашей системе «отправлено» → «вернулось». Состав: ФИО водителя,
гос.номер, ООО/ИП перевозчика, ИНН перевозчика, номера блоков (буква+номер),
вес, стоимость. Интеграции с ЭДО **нет** — только отражение факта.

## Конструктор ТТН

Цель — **внутрь новой программы (вариант А)**. На время перехода работает
РУМЕКС-SQLite как временное решение (**Б**), которое потом убирается.

## Переход

- **11.10.2026 — дата импорта данных** и дата старта отчётов новой программы;
  старая работает своим чередом, параллельно.
- **Переключение — отдельно, по готовности** всех модулей и контуров (дата X
  ещё не выбрана). В день переключения переносится состояние: блоки, вагоны,
  машины, кто где лежит.
- Стратегия: **строим новое рядом, пока старое работает**, чтобы не остановить
  производство. Мост и РУМЕКС-SQLite живут до переключения.
- Обкатка: с 11.10 новая считает свои отчёты, старая свои — сверка расхождений.
  Владелец сам вносит тестовые данные (6 машин, 16 блоков) с 12.10.

## Порядок этапов

0. Договориться и записать (README + память) — **выполняется**.
1. Справочники (админ): машины, вагоны со схемами, перевозчики, водители,
   веса по буквам, сетка, три тупика.
2. Роли, вход, журнал действий.
3. Диспетчер: приёмка блоков, id от рождения, ТТН (конструктор сразу А).
4. Бухгалтеры: проверка, ЭР, статусы.
5. Операторы: приёмка машины, выгрузка, вагон, схема, тупики, Кодар, возврат.
6. История: блок / машина / вагон.
7. Переключение с переносом состояния на дату X.
8. Фото (S3) — последним, отдельно.

## Незакрытое

- Дата X (переключение) не выбрана — по готовности модулей.
- Способ обкатки: как вводить данные параллельно в старую и новую.
- Внутри роли «оператор» разбивка по сменам/постам не утверждена.
- Есть ли отдельный журнал по водителям/перевозчикам, или хватает фильтра по
  рейсам — не решено (склонность: справочники + снимок в рейсе).
- Куда деваются уже написанные мост и РУМЕКС-таблицы при переключении —
  не решено (пока живут).
